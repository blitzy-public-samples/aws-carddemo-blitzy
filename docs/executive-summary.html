Flow 1

Sign-on, then authenticated account inquiry

sequenceDiagram
  autonumber
  participant C as HTTP client
  participant R as Router COAPIRTR
  participant S as Auth COAPISEC
  participant A as COACSVCC
  C->>R: POST sign-on with user id and password
  R->>S: validate credentials against USRSEC
  S-->>R: short-lived bearer token
  R-->>C: 200 token issued
  C->>R: GET account by id with bearer token
  R->>S: validate token
  S-->>R: token accepted
  R->>A: read ACCTDAT read-only
  A-->>R: account record
  R-->>C: 200 JSON account

The Contract

Seven read-only endpoints

MethodPathPurpose
POST/carddemo/api/v1/signonAuthenticate a user; issue a bearer token
GET/carddemo/api/v1/accounts/{acctId}Account status, balances, limits, dates
GET/carddemo/api/v1/customers/{custId}Customer demographics (PII minimized)
GET/carddemo/api/v1/cards/{cardNum}Card detail (PAN masked, CVV excluded)
GET/carddemo/api/v1/xref/{cardNum}Resolve card to account and customer
GET/carddemo/api/v1/accounts/{acctId}/transactionsList transactions for an account
GET/carddemo/api/v1/transactions/{tranId}Single transaction detail

Security

Sensitive data protected by default

PAN masked to last 4
CVV never returned
SSN & gov-id masked
Bearer token vs USRSEC
  • Uniform error envelope and a fixed HTTP status map.

Risks & Mitigations

Managed Risk

Known risks, deliberate mitigations

RiskMitigation
Cleartext HTTP, no transport auth this incrementLoopback-only listener; documented TLS/keyring and RACF follow-up
Stateless, pseudo-conversational CICSToken registry in a MAIN TSQ with a short 15-minute life
No card or account transaction indexApplication-level filtering now; pagination and index later
Oversized transaction list payloadsCICS channel and container transport, not COMMAREA
Sensitive PII exposurePAN last-4, CVV omitted, SSN and gov-id masked by default
