06

Business value

07
What changed

The architecture creates room to change safely

What changed What it makes possible
Balance updates begin at authorization instead of a nightly batch window. Account state can reflect accepted transactions without waiting for the scheduled chain.
Fraud detection reads an event that already existed and had no counterpart in the original system. A new capability can arrive without changing the authorization service.
Each service owns its datastore. Deployments and schema changes stay inside an explicit boundary.
Sixty-six flagged source rules carry file and line citations. Owners can approve behavior changes without guessing at source intent.

Risk and mitigation

12
Known risk

Risk is visible and testable

Risk Mitigation
Parity uses documented behavior and checked-in sample data, not a live original run. The equivalence suite is a required build stage, and its results are published.
Two known source defects remain for parity. Each defect is reproduced, cited, and held for an owner decision.
The sample data cannot reach the narrowed-precision boundary. A synthetic boundary test now covers the source behavior directly.
A later edit could change monetary rounding. A dedicated test fails when truncation changes.
