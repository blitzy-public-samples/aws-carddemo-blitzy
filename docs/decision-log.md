# CardDemo Modernization — Decision Log

This log records every non-trivial engineering decision, and every deviation from a literal reading of the requirements, taken while re-platforming the AWS CardDemo mainframe application (COBOL / CICS / VSAM / JCL / BMS on z/OS) to a cloud-native Java 21 / Spring Boot 4.1.0 microservices and React 19 stack. It is a first-class deliverable of the Explainability rule (AAP §0.7.2): rationale lives here, in this log, rather than in code comments. Each row names the decision, the alternatives that were weighed, the rationale, and the residual risk. Every deviation from a literal interpretation of the requirements has an explicit entry so the migration remains fully auditable.

**Legend.** Locators in square brackets — e.g. `[app/cbl/COSGN00C.cbl:L135-136]` — point to the authoritative legacy source (`path:line-range`) that grounds the decision. Legacy COBOL identifiers are quoted verbatim, including preserved source misspellings such as `ACCT-EXPIRAION-DATE`. Every table below uses the identical four columns — **Decision | Alternatives | Rationale | Risk** — as prescribed by AAP §0.7.3.

## 1. Platform & Build

| Decision | Alternatives | Rationale | Risk |
|----------|--------------|-----------|------|
| Target Spring Boot 4.1.0 | Spring Boot 3.5.x (EOL 2026-06-30) | A green-field build should adopt the supported major with the longest runway; 4.1.0 manages Spring Framework 7.0.8 and all starter versions | New major; verified compatible with Java 21 and Spring Cloud 2025.1.2 |
| Microservices decomposition | Retain a single-monolith shape | The prompt explicitly mandates a microservices architecture, one service per bounded feature | Distributed-transaction and session complexity, mitigated by per-service ownership |
| BOM-managed library versions | Pin every library version explicitly | Resolving Spring-ecosystem versions transitively through the Spring Boot BOM (which pins Spring Framework 7.0.8) avoids version conflicts and matches Spring guidance | None; the anchors (Spring Boot 4.1.0, Spring Cloud 2025.1.2, PostgreSQL 18.4) remain explicitly pinned |
| Java 21 (Eclipse Temurin) LTS | Java 17 or a non-LTS release | Pinned by the prompt; longest LTS runway | None (anchor) |
| Apache Maven 3.9.16 | Apache Maven 4 | Maven 4 is still RC; 3.9.16 is the current stable release | None |
| Frontend built via npm / Vite on Node.js 24, not as a Maven module | Wrap the frontend inside the Maven build | The React 19 / Vite toolchain is idiomatic for the SPA and keeps the two build boundaries clean | Two build systems to orchestrate (documented in README-target.md) |
| Spring Cloud 2025.1.2 (Oakwood) BOM applied to the `api-gateway` only | Apply the Spring Cloud BOM to every service | Only the `api-gateway` needs Spring Cloud Gateway routing; scoping the BOM to that one module avoids unnecessary coupling for the other services | None; other services depend solely on the Spring Boot parent BOM |

## 2. Data & Persistence

| Decision | Alternatives | Rationale | Risk |
|----------|--------------|-----------|------|
| PostgreSQL 18.4 | PostgreSQL 19 (beta) | Only the 18.x line is GA; a beta release is not production-safe | None |
| Financial precision — COMP-3 packed decimal → `BigDecimal` on `NUMERIC(p,s)` | Use native `double` / `float` | COBOL packed-decimal arithmetic must remain byte-identical; the monthly-interest `COMPUTE WS-MONTHLY-INT = ( TRAN-CAT-BAL * DIS-INT-RATE) / 1200`, where `WS-MONTHLY-INT` is `PIC S9(09)V99`, maps to multiply-then-divide-by-1200 that preserves the operand order and intermediate scale and **truncates toward zero** at the receiver scale — `setScale(2, RoundingMode.DOWN)`, NOT `HALF_UP`. The COBOL `COMPUTE` carries no `ROUNDED` phrase, so excess fractional digits are dropped (e.g. `0.125 → 0.12`, never `0.13`; `0.41666… → 0.41`), as enforced by `FinancialPrecisionTest`. Account monetary fields are `PIC S9(10)V99` (12 digits, scale 2) → `NUMERIC(12,2)` | A rounding-mode or scale mismatch would diverge financial output; using `HALF_UP` would incorrectly round `.005` boundaries up `[app/cbl/CBACT04C.cbl:L168,L464-465; app/cpy/CVACT01Y.cpy:L4-17]` |
| Interest DEFAULT-group fallback preserved | Omit the fallback | When the disclosure-group lookup returns file status `23` (not found), `CBACT04C` substitutes the literal group id `DEFAULT` and re-reads; `InterestCalculationService` reproduces this fallback exactly | Divergent interest for accounts missing a disclosure group `[app/cbl/CBACT04C.cbl:L436-438]` |
| Optimistic locking via JPA `@Version` | Pessimistic database locking | `COACTUPC` implements a read-snapshot-compare-rewrite pattern with no file locking; its 88-levels `COULD-NOT-LOCK-ACCT-FOR-UPDATE`, `COULD-NOT-LOCK-CUST-FOR-UPDATE`, `DATA-WAS-CHANGED-BEFORE-UPDATE` (message "Record changed by some one else. Please review") and `LOCKED-BUT-UPDATE-FAILED` describe the outcomes; a JPA `@Version` column reproduces the observable "please review" conflict result on concurrent modification | Behavior preserved; adds a version column with no legacy analogue `[app/cbl/COACTUPC.cbl:L517-523]` |
| Multi-file update → single `@Transactional` unit | Independent, separately-committed writes | `COACTUPC` performs a dual `REWRITE` — account file then customer file, each with its own RESP check; these become one `@Transactional` service method so both updates commit or roll back together | Broken atomicity would corrupt referential state `[app/cbl/COACTUPC.cbl:L4066-4090]` |
| Referential integrity → database FK constraints + service validation | Keep application-only enforcement | Legacy code enforces integrity by COBOL read order (cross-reference `CVACT03Y` → account); the target adds declarative foreign keys plus service-layer checks to guarantee 100% integrity | FK ordering / cascade differences must be validated `[app/cbl/CBTRN02C.cbl:L371-397; app/cpy/CVACT03Y.cpy]` |
| Database sequence / identity for the transaction id | Reproduce the browse-last-then-increment approach | `COTRN02C` generates an id by `MOVE HIGH-VALUES TO TRAN-ID`, `STARTBR` / `READPREV` / `ENDBR` to the last record, then `MOVE TRAN-ID TO WS-TRAN-ID-N` and `ADD 1` — a race-prone pattern under concurrency; a database sequence guarantees uniqueness while the observable 16-digit zero-padded form (`WS-TRAN-ID-N PIC 9(16)`) is preserved on the wire | Generation mechanism changes; observable id format preserved `[app/cbl/COTRN02C.cbl:L444-451]` |
| Single `carddemo` PostgreSQL database with per-service least-privilege DB roles | One physical database per service | A single `carddemo` database keeps the topology simple while each service authenticates with its OWN role rather than a shared owner. Local Docker Compose uses one externalized owner role for simplicity; Kubernetes provisions per-service roles (`carddemo-<svc>`) via distinct Secrets (`k8s/secret.yaml`), and the `api-gateway` — which owns no database — is issued NO database Secret. The bootstrap owner (`carddemo-postgres-bootstrap`) is used by a DB-init step to `CREATE ROLE` / `GRANT` each service's least-privilege role over just the tables that service owns | Role-provisioning must run before services connect; the DB-init migration is delivered with the bootable services. Consistent with `docker-compose.yml` and `k8s/secret.yaml` |

## 3. Security & Session

| Decision | Alternatives | Rationale | Risk |
|----------|--------------|-----------|------|
| BCrypt password encoder (credentials hashed at rest) | Preserve the legacy plaintext comparison | Plaintext credentials are unacceptable at rest, so authentication moves to a one-way encoder. `COSGN00C` upper-cases BOTH the entered user id and the entered password before a plaintext equality check `IF SEC-USR-PWD = WS-USER-PWD`, which makes today's authentication effectively case-insensitive; moving to a standard encoder makes it case-sensitive. This is a deliberate, observable behavior change, logged here per the Explainability rule (either accept case-sensitivity or upper-case before hashing to retain legacy behavior) | Behavior change: case-insensitive → case-sensitive password matching `[app/cbl/COSGN00C.cbl:L132,L135-136,L223]` |
| Spring Session (Redis) for externalized state | In-memory HTTP session | COMMAREA state must survive across stateless, independently-scaled services, so session state is externalized to Redis 8 | Requires a Redis dependency (documented) `[app/cpy/COCOM01Y.cpy:L18-45]` |
| Sensitive-field encryption at rest + response masking; TLS in transit as a deploy-layer control | Store and return raw values | SSN, government id, EFT account id, and CVV are encrypted at rest by an AES-GCM JPA `@Converter` (`CryptoConverter`, key supplied by the environment) and masked out of JSON responses via `@JsonIgnore` on the sensitive getters — both IMPLEMENTED in `carddemo-common`. TLS in transit is a deployment-layer concern (ingress / service mesh terminates TLS) rather than application code; Redis AUTH is enforced now (`--requirepass`) with Redis TLS documented as a production follow-up. A new security posture with no legacy field-level analogue | Encryption-key management is environment-supplied; TLS termination and Redis TLS are configured at deploy time, not in this tranche `[app/cbl/COSGN00C.cbl]` |
| Role mapping `SEC-USR-TYPE` `'A'` / `'U'` → `ROLE_ADMIN` / `ROLE_USER` | Ad-hoc per-endpoint role checks | Preserves the two-role model expressed by the 88-levels `CDEMO-USRTYP-ADMIN` (VALUE `'A'`) and `CDEMO-USRTYP-USER` (VALUE `'U'`); on success `COSGN00C` copies `SEC-USR-TYPE` into the COMMAREA and routes admins to `COADM01C`, others to `COMEN01C` | Must gate admin-only user CRUD identically `[app/cpy/COCOM01Y.cpy:L26-30; app/cpy/CSUSR01Y.cpy:L22; app/cbl/COSGN00C.cbl:L227,L231-237]` |

## 4. Behavioral Fidelity & Presentation

| Decision | Alternatives | Rationale | Risk |
|----------|--------------|-----------|------|
| Reject codes 100–103 reproduced exactly (`TransactionPostingJob`) | Simplify or renumber the reject codes | `CBTRN02C` validates in a fixed order — cross-reference then account, short-circuiting when the earlier lookup fails — and emits `100` "INVALID CARD NUMBER FOUND", `101` "ACCOUNT RECORD NOT FOUND", `102` over-limit (computed as `WS-TEMP-BAL = ACCT-CURR-CYC-CREDIT - ACCT-CURR-CYC-DEBIT + DALYTRAN-AMT` compared to `ACCT-CREDIT-LIMIT`, NOT against the current balance), and `103` account-expired (`ACCT-EXPIRAION-DATE >= DALYTRAN-ORIG-TS (1:10)`); the posting job preserves the identical code-to-condition mapping and the 430-byte reject record (350-byte transaction image + 80-byte trailer: `PIC 9(04)` reason + `PIC X(76)` description) | Downstream reject consumers depend on the exact codes and byte layout `[app/cbl/CBTRN02C.cbl:L176-182,L371-397,L380-421]` |
| Pseudo-conversational COMMAREA → stateless REST + externalized `SessionContext` | Sticky server-side HTTP sessions | CICS carried cross-screen state in the COMMAREA (`COCOM01Y`) and transferred control with `XCTL`; the target uses stateless controllers with a `SessionContext` held in Spring Session (Redis) / JWT claims, and replaces `XCTL` program transfer with a gateway route or HTTP redirect plus a role check. The context 88-levels `CDEMO-PGM-ENTER` (VALUE `0`) / `CDEMO-PGM-REENTER` (VALUE `1`) and `CDEMO-LAST-MAP PIC X(7)` are preserved as `SessionContext` state | Session-store dependency; observable navigation behavior preserved `[app/cpy/COCOM01Y.cpy:L18-45; app/cbl/COSGN00C.cbl:L231-237]` |
| Date validation `CEEDAYS` / Lillian → `java.time` STRICT parsing (`DateUtil`) | Lenient date parsing | `CSUTLDTC` validates dates by calling the Language Environment `CEEDAYS` service and converting to a Lillian day count (`OUTPUT-LILLIAN PIC S9(9) BINARY`); `DateUtil` uses `LocalDate.parse` with a `DateTimeFormatter` set to `ResolverStyle.STRICT`, treats severity zero as valid, and maps each feedback category (`FC-INVALID-DATE`, `FC-INVALID-ERA`, `FC-INVALID-MONTH`, `FC-BAD-PIC-STRING`) to an equivalent validation result. To match the Lillian calendar range it rejects dates before the Gregorian epoch `1582-10-15` and rejects year zero / zero-padded-out-of-range input; it returns the result in the 15-character contract width and takes an injectable `java.time.Clock` so "today"-relative checks are deterministic in tests | Edge-case date semantics (pre-1582, year zero, padding, clock) must match `[app/cbl/CSUTLDTC.cbl:L2,L60-77]` |
| BMS 3270 mapsets → plain React 19 + CSS (no component library) | Adopt a named component library / design system | The prompt names no component library or design system, so each 24×80 mapset becomes a React function component using plain React with CSS, preserving field labels, tab order, password masking, and PF-key actions (ENTER submit, PF3 exit, PF7 / PF8 paging) | Visual parity is hand-maintained `[app/bms/]` |

## 5. Source-Inventory Reconciliation

| Decision | Alternatives | Rationale | Risk |
|----------|--------------|-----------|------|
| Program count reconciled to 28 `.cbl` / `.CBL` programs (17 online + 10 batch + 1 utility) | Accept the prompt's "33 programs (17 online + 16 batch)" | Repository evidence is authoritative: 17 online `CO*` + 10 batch `CB*` + 1 utility (`CSUTLDTC`) = 28; the "16 batch" figure most plausibly refers to batch JCL job streams (29 present), not batch COBOL programs | Mismap risk if the stale count were used `[app/cbl/; app/jcl/]` |

| Exclude `app/cpy/UNUSED1Y.cpy` from active transformation | Transform all copybooks uniformly | It is an unused copybook with no consuming program | None; recorded for auditability `[app/cpy/UNUSED1Y.cpy]` |

## 6. Infrastructure, Observability & Review-Surfaced Deviations

Additional non-literal choices and deviations made while delivering the foundation tranche. Each is recorded here per the Explainability rule so the migration stays auditable.

| Decision | Alternatives | Rationale | Risk |
|----------|--------------|-----------|------|
| `DailyTransaction` is a plain POJO, NOT a JPA `@Entity` | Persist the daily feed as its own table | `CVTRA06Y` describes the daily-transaction FEED record consumed by the posting batch job, not a stored master table; the job reads the feed and writes `Transaction` rows. Modeling it as a non-persistent read model avoids a spurious table with no legacy datastore analogue | None; keeps the schema faithful to the VSAM inventory `[app/cpy/CVTRA06Y.cpy]` |
| Redis requires `--requirepass` AUTH + network isolation + no host exposure | Leave Redis open (image default) | Legacy CICS had no external session store; an unauthenticated, host-exposed Redis is a CWE-306 exposure. Redis now demands a password (externalized secret), is `ClusterIP`/no-published-port only, and is reachable solely by the services + gateway (NetworkPolicy) | Redis TLS in transit is a documented production follow-up (needs cert management) |
| Spring Session values serialized with a strict, allowlisted JSON serializer (`SessionRedisConfig`) | Default JDK (Java native) serialization | Native deserialization of session bytes is a CWE-502 risk; `GenericJacksonJsonRedisSerializer` + `BasicPolymorphicTypeValidator` (allowlist `com.carddemo.*`, `java.util.*`, `java.time.*`, `java.lang.*`) removes it. `carddemo-common` exposes no auto-configuration, so each service activates it via `@Import(SessionRedisConfig.class)` or by component-scanning `com.carddemo.common` | Allowlist must cover every persisted session type; activation is explicit per service |
| All credentials externalized to required env / per-service Secrets; observability UIs bound to loopback | Commit convenient default credentials | Predictable `carddemo/carddemo` and `admin/admin` defaults are a CWE-798 exposure. Compose uses `${VAR:?}` (fail-fast, `.env`-supplied); Kubernetes uses per-service Secret templates (SealedSecrets/ESO in real environments); Grafana admin is externalized; Prometheus/Grafana publish only on `127.0.0.1` | Operators must populate `.env` / inject real secrets before startup |
| Actuator health `show-details: when-authorized`; Prometheus scrape authenticated | `show-details: always`, anonymous scrape | Anonymous health detail / metrics leak internal topology (dependency hosts, versions). Detail renders only to an authenticated principal; Prometheus presents a dedicated `monitoring` principal (password from a mounted secret) | The service-side `monitoring` principal + management-chain HTTP basic are delivered with the bootable services; the scrape wiring is inert until then |
| Trace sampling 0.1 for services, 1.0 for the `api-gateway` | Uniform 1.0 everywhere | The gateway is the entry point, so sampling every request there starts each trace; downstream services sample 0.1 to bound overhead. The gateway overrides the shared `0.1` via an explicit Deployment env var (explicit `env` wins over `envFrom`) | Trace continuity relies on context propagation across the 0.1/1.0 boundary (standard for head-based sampling) |
| Production container hardening (non-root, seccomp, dropped caps, read-only FS, NetworkPolicy, PDB) | Run images with default privileges | Defense-in-depth (MJ-10): every pod runs `runAsNonRoot` with a `RuntimeDefault` seccomp profile, drops all Linux capabilities (the frontend re-adds only `NET_BIND_SERVICE`), uses a read-only root filesystem with `emptyDir` scratch, a default-deny `NetworkPolicy` with least-privilege allows, and `maxUnavailable: 1` PodDisruptionBudgets | Datastores use a lighter profile so the official images initialize correctly; documented per workload |
| Compose health probe uses bash `/dev/tcp`; images built by multi-stage Dockerfiles | `curl`-based healthcheck; copy a prebuilt JAR | The `eclipse-temurin:21-jre` base ships no `curl`/`wget`, so the probe issues a minimal HTTP request over bash `/dev/tcp`. Images run the Maven reactor build in-stage (no prebuilt-JAR copy) so a clean clone builds end-to-end | The per-service Dockerfiles are delivered with the bootable services; `docker compose config` validates the topology until then `[docker-compose.yml]` |
| React `Header` shows a render-time date/time snapshot (server-preferred), not a live ticking clock | A `setInterval` browser clock | COBOL `POPULATE-HEADER-INFO` takes a single `FUNCTION CURRENT-DATE` snapshot at map-send time; the component prefers the server-provided `currentDate`/`currentTime` and otherwise takes one client snapshot, never ticking — matching legacy behavior and avoiding a spurious live clock | None; matches the legacy single-snapshot semantics `[app/cbl/COSGN00C.cbl]` |
| SPA calls same-origin `/api`, reverse-proxied by nginx; nginx ships as a full main config | Bake an absolute gateway URL into the bundle; nginx `conf.d` snippet | A static Vite bundle cannot consume runtime env, so an absolute gateway URL is unworkable across environments; the bundle uses the relative `/api` base and nginx proxies it to the gateway on the private network. The nginx file is a complete main config (the frontend `Dockerfile` copies it to `/etc/nginx/nginx.conf`, not `conf.d`), and under the read-only root filesystem nginx writes only to mounted `emptyDir`s (`/var/cache/nginx`, `/var/run`, `/tmp`) | The frontend `Dockerfile` must honor the main-config placement and writable-path contract `[frontend/nginx.conf]` |
| Commit `frontend/package-lock.json` as an authorized deliverable | `.gitignore` the lockfile; regenerate on each build | AAP §0.5.1 mandates the npm toolchain is "lock-pinned at scaffold", and the documented `npm ci` build REQUIRES a committed lockfile for reproducible, deterministic installs; omitting it would break `npm ci` and allow silent transitive-version drift. Reviewed: `lockfileVersion: 3`, 491 locked entries, root `dependencies`/`devDependencies` exactly consistent with `frontend/package.json`. It is therefore recorded in the traceability matrix (Section 11) as a standalone-operation deliverable, resolving its earlier "undeclared file" flag | Lockfile must be regenerated (and re-reviewed) whenever `package.json` dependencies change `[frontend/package.json; frontend/package-lock.json]` |
