📋 API Overview

Migration Context: This REST API represents the complete modernization of the CardDemo mainframe application. All COBOL EXEC CICS SEND MAP/RECEIVE MAP commands have been replaced with REST JSON request/response patterns, providing a cloud-native, scalable alternative to the original CICS transaction processing system.

Base URL

http://localhost:8080/api

Technology Stack

  • Framework: Spring Boot 3.4.5
  • Java Version: Java 21 LTS
  • Security: Spring Security 6.4.x with JWT authentication
  • Database: PostgreSQL 16.x
  • Documentation: SpringDoc OpenAPI 2.6.0

API Controllers

Controller Base Path COBOL Programs Replaced Function
AuthController /api/auth COSGN00C User authentication and session management
MenuController /api/menu COMEN01C, COADM01C Navigation menus for users and administrators
AccountController /api/accounts COACTUPC, COACTVWC Account inquiry, creation, and updates
CardController /api/cards COCRDLIC, COCRDSLC, COCRDUPC Credit card management operations
TransactionController /api/transactions COTRN00C, COTRN01C, COTRN02C Transaction processing and inquiry
BillingController /api/billing COBIL00C Billing statement generation and retrieval
ReportController /api/reports CORPT00C Report generation and management
UserController /api/users COUSR00C, COUSR01C, COUSR02C, COUSR03C User administration (CRUD operations)
HealthCheckController /api/health N/A (New capability) Application health monitoring

🔐 Authentication & Authorization

JWT Authentication Scheme

The CardDemo API uses JWT (JSON Web Token) for authentication, replacing the mainframe RACF security system. All endpoints except /api/auth/login and /api/health require a valid JWT token in the Authorization header.

Obtaining a Token

Send a POST request to /api/auth/login with valid credentials to receive a JWT token.

POST /api/auth/login
Content-Type: application/json

{
  "userId": "ADMIN001",
  "password": "yourPassword"
}

Using the Token

Include the JWT token in the Authorization header of all subsequent requests:

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Role-Based Access Control (RBAC)

The API implements role-based access control with three primary roles:

Role Access Permissions RACF Equivalent
ROLE_ADMIN Full system access including user management and administrative functions RACF Administrator
ROLE_USER Access to accounts, cards, and transactions; read-only for reports RACF Standard User
ROLE_OPERATOR Access to batch operations and operational reports RACF Operator

Access Control by Endpoint

  • Public Access (no JWT required):
    • POST /api/auth/login
    • GET /api/health
  • ROLE_ADMIN only:
    • All /api/users/** endpoints
    • GET /api/menu/admin
  • ROLE_USER or higher:
    • All /api/accounts/** endpoints
    • All /api/cards/** endpoints
    • All /api/transactions/** endpoints
    • All /api/billing/** endpoints
  • ROLE_OPERATOR or higher:
    • All /api/reports/** endpoints

Token Expiration

JWT tokens expire after 1 hour. Clients must obtain a new token by re-authenticating when receiving a 401 Unauthorized response.

🔑 AuthController

Base Path: /api/auth

COBOL Program: COSGN00C.cbl (Signon Screen)

Function: Handles user authentication and session management, replacing CICS signon screen functionality.

POST /api/auth/login Public

Authenticates a user with userId and password, returning a JWT token for subsequent API calls. Replaces COBOL EXEC CICS READ FILE('USRSEC') for user validation.

Request Body

{
  "userId": "ADMIN001",
  "password": "SecurePass123!"
}

Request Parameters

Field Type Required Description COBOL Field
userId String Yes User ID (8 characters max) WS-USER-ID
password String Yes User password (8-100 characters) WS-USER-PWD

Success Response (200 OK)

{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJBRE1JTjAwMSIsInJvbGVzIjpbIlJPTEVfQURNSU4iXSwiaWF0IjoxNzE2MjM5MDIyLCJleHAiOjE3MTYyNDI2MjJ9.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c",
  "expiresIn": 3600,
  "userType": "A",
  "userId": "ADMIN001",
  "firstName": "John",
  "lastName": "Administrator"
}

Error Response (401 Unauthorized)

{
  "timestamp": "2025-01-15T10:30:00.000Z",
  "status": 401,
  "error": "Unauthorized",
  "message": "Invalid userId or password",
  "path": "/api/auth/login"
}
POST /api/auth/logout JWT Required

Invalidates the current JWT token and logs out the user. Replaces COBOL EXEC CICS RETURN with session termination.

Request Headers

Authorization: Bearer {jwt-token}

Success Response (200 OK)

{
  "message": "Successfully logged out",
  "timestamp": "2025-01-15T10:35:00.000Z"
}

📡 HTTP Response Codes

The CardDemo API uses standard HTTP response codes to indicate the success or failure of API requests.

Success Codes

Code Status Description COBOL Equivalent
200 OK Request succeeded. The response body contains the requested data. RESP=DFHRESP(NORMAL)
201 Created Resource created successfully. Returned for POST operations. EXEC CICS WRITE FILE(...) END-EXEC
204 No Content Request succeeded but there's no content to return. RESP=DFHRESP(NORMAL) with no data

Client Error Codes

Code Status Description COBOL Equivalent
400 Bad Request Request is malformed or contains invalid parameters. Check validation errors in response. APPL-RESULT validation errors
401 Unauthorized Authentication failed or JWT token is missing/invalid/expired. RACF authentication failure
403 Forbidden User is authenticated but lacks permission to access the resource. Check role requirements. RACF authorization failure
404 Not Found Requested resource does not exist. Verify IDs and paths. FILE-STATUS 23 (record not found)
409 Conflict Request conflicts with current state (e.g., duplicate key violation). FILE-STATUS 22 (duplicate key)

Server Error Codes

Code Status Description COBOL Equivalent
500 Internal Server Error Unexpected server error occurred. Check logs for details. EXEC CICS ABEND
503 Service Unavailable Service is temporarily unavailable (database down, maintenance mode). CICS region unavailable

Error Response Format

All error responses follow a standard format:

{
  "timestamp": "2025-01-15T10:30:00.000Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed for field 'acctCreditLimit': must be greater than 0",
  "path": "/api/accounts/12345678901",
  "validationErrors": [
    {
      "field": "acctCreditLimit",
      "message": "must be greater than 0",
      "rejectedValue": -1000
    }
  ]
}

COBOL Error Code Mapping

The following table maps common COBOL error conditions to HTTP response codes:

COBOL Condition HTTP Code Notes
RESP=DFHRESP(NORMAL) 200 OK Successful operation
FILE-STATUS 23 (record not found) 404 Not Found Entity does not exist
FILE-STATUS 22 (duplicate key) 409 Conflict Primary key violation
APPL-RESULT validation errors 400 Bad Request Business rule violations
RACF UACC(NONE) 403 Forbidden Insufficient permissions
EXEC CICS ABEND 500 Internal Server Error System error requiring investigation

🔢 Data Types & Field Mappings

Understanding the mapping between COBOL copybook data types and JSON/Java types.

COBOL to JSON Type Mapping

COBOL Data Type Example JSON Type Java Type Notes
PIC 9(11) Account ID number Long 11-digit integer
PIC S9(10)V99 COMP-3 Currency amount number BigDecimal Precision preserved with scale 2
PIC X(16) Card number string String Alphanumeric, trailing spaces trimmed
PIC 9(8) Date (CCYYMMDD) string LocalDate Format: YYYY-MM-DD
PIC X(01) Status flag string String Single character (Y/N)
88-level condition ACCT-ACTIVE VALUE 'Y' boolean boolean Converted to true/false

Copybook Structure Examples

Account Record (CVACT01Y.cpy)

COBOL:
01 ACCOUNT-RECORD.
   05 ACCT-ID                  PIC 9(11).
   05 ACCT-ACTIVE-STATUS       PIC X(01).
   05 ACCT-CURR-BAL            PIC S9(10)V99 COMP-3.
   05 ACCT-CREDIT-LIMIT        PIC S9(10)V99 COMP-3.

JSON:
{
  "acctId": 12345678901,
  "acctActiveStatus": "Y",
  "acctCurrBal": 5432.10,
  "acctCreditLimit": 10000.00
}

Card Record (CVACT02Y.cpy)

COBOL:
01 CARD-RECORD.

🔄 Migration Notes

COBOL to REST API Transformation

Key architectural changes in the migration from COBOL/CICS to Spring Boot REST:

Screen I/O Replacement: All COBOL EXEC CICS SEND MAP and RECEIVE MAP commands have been replaced with REST API JSON request/response patterns. BMS map fields are now represented as JSON properties in request/response bodies.
File I/O Replacement: VSAM file operations (READ, WRITE, REWRITE, DELETE) are replaced by JPA repository methods accessing PostgreSQL. Primary keys and alternate indexes are preserved as database indexes.
Transaction Management: COBOL EXEC CICS SYNCPOINT commands are replaced by Spring @Transactional annotations, providing equivalent transaction boundaries and rollback capabilities.
Numeric Precision: COBOL COMP-3 packed decimal fields are converted to Java BigDecimal with appropriate scale and rounding modes to ensure bit-identical financial calculations.

Performance Characteristics

  • Response Time Target: Sub-200ms for card authorization requests (95th percentile)
  • Throughput Target: 10,000 transactions per second sustained
  • Horizontal Scaling: 3-10 backend pod replicas based on CPU utilization (70% threshold)
  • Database Query Performance: Sub-10ms for primary key lookups via PostgreSQL B-tree indexes
